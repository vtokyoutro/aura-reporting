# Сборка AURA с аватарами

`npm run build:avatars` выполняет TypeScript-проверки и собирает основной каталог `out` с включёнными аватарами. Флаг передаётся только процессу сборки. Команда не меняет `.env`, не устанавливает приложение и не публикует артефакты.

Обычный `npm run build` сохраняет прежнее поведение: значение берётся из текущего окружения Vite. Для повторяемой релизной сборки с аватарами используйте именно `build:avatars`; не задавайте флаг глобально. Не запускайте затем `build:win`, поскольку он повторно выполняет обычную сборку. Упаковка уже проверенного `out` должна быть отдельным согласованным действием с запретом публикации.

Локальные тестовые сборки и профили `out/avatar-ui-*`, тестовые модули и `.env*` исключены из установщика. Storage-стенд с идентификаторами реальных тестовых аккаунтов остаётся локальным и исключён из Git.

Storage и UI-приёмка выполнены пользователем с обычными тестовыми аккаунтами. Доступ чтения разрешён сотрудникам, изменение — только владельцу. SQL-файлы ревью отражают историческое предложение: не применять их повторно поверх вручную проверенных политик. Сборка не изменяет Supabase, RLS или Auth.

Перед распространением нужны отдельная проверка упакованной Windows-сборки в изолированном профиле, решение о подписи и разрешение на публикацию. Проверки CDN в локальных тестах подтверждают защиту от поздних ответов, но не мгновенную синхронизацию между устройствами.
